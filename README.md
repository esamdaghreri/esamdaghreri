### How I think about engineering

- **Business first, code second.** Understanding the domain is the hard part; the code is the easy part once you do.
- **The simplest correct thing wins.** Three clear lines beat a clever abstraction. Boring and reliable beats impressive.
- **If it isn't written down, it doesn't exist.** Reasoning that lives only in someone's head can't scale or be trusted.
- **AI-native by default.** Domain knowledge, docs, and workflows are living systems that engineers and AI agents share — it's how a small team ships fast without losing the *why*.
- **Leverage over output.** A leader's job is to multiply the team, not out-code it.
